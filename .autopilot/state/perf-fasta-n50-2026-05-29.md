**Wall-clock ratio: 7.61× faster (PASS)**

## Optimization history
- 0.1.0: per-byte 4-comparison branch → 2.07× SLOWER than seqkit (FAIL)
- 0.1.1: 256-entry GC lookup table → 7.6× FASTER (PASS)

## Notes
- Speedup: GC lookup table replaces 4 comparisons + 3 OR-branches per byte
  with a single array indexing. LLVM can auto-vectorize the `sum()` iterator
  over `GC[b]` but not the branch-chain. 6× CPU speedup on this FASTA size.
- Wall-clock variance is HDD latency noise (SSD read-ahead); CPU (7.2×) stable.
- seqkit stats uses goroutines (multi-threaded by default); single-thread
  comparison is the fair baseline since ours is always single-threaded.
