## Couplings that block a shallow reimplementation

- Sample clustering is not merely a group label. It includes references when `cluster_by_groups=TRUE`; `partition_method='none'` still computes `parallelDist` + hierarchical clustering for groups with >2 cells, then one named cluster, while groups of <=2 have no dendrogram. Subcluster mode may first exclude reference outlier genes **for clustering only**, then use Seurat PCA/SNN or RANN+igraph Leiden and join cluster trees via `ape`. Per-chromosome memberships are another object when enabled. `R/inferCNV_tumor_subclusters.R:34-72,91-160,181-265,569-643,699-740`.
- i6 cannot be reproduced from the step-14 real matrix alone: with `HMM=TRUE` it builds a synthetic hidden spike at **step 3** from reference groups (all observations as proxy when none), using sampled genes and simulated 0.01/0.5/1/1.5/2/3 CNV regions. It propagates through earlier transforms; stage 15 also mirrors clustering into the spike. i6 emissions come from spike mean/SD plus a stochastic group-size SD fit. The literal loop makes an `ncells × 100` sample matrix, takes **row means**, then `sd(means)`; at `ncells=1`, `replicate` simplifies to a vector, the code takes one overall mean and then its SD. This is a future oracle question, not permission to substitute column means or analytical standard error. `HiddenMarkov::dthmm` and adjusted Viterbi run independently per chromosome and selected group. `R/inferCNV_ops.R:583-599`; `R/inferCNV_hidden_spike.R:3-25,30-44,72-164,170-213`; `R/inferCNV_tumor_subclusters.R:155-160`; `R/inferCNV_HMM.R:15-29,154-210,230-264,345-408,509-613`. Preserve seed/RNG context in any future oracle.
- i3 is a different statistical model, not six-state i6 with states removed: it derives normal/proxy `mu` and `sigma`, computes Z- or HoneyBADGER/KS-derived mean shifts, uses three Gaussian emissions and a neutral-biased initial state. Sample-mode predictions aggregate expression by group and chromosome; cell/subcluster dispatch uses separate functions. `R/inferCNV_i3HMM.R:17-80,99-155,332-387`; `R/inferCNV_ops.R:1251-1307`.
- Bayesian filtering uses packaged BUGS model files (`system.file("BUGS_Mixture_Model...", package="infercnv")`), `rjags`/JAGS, 3 or 6 chains, 500 adaptation, 200 burn-in, 1000 samples; it is not a deterministic threshold directly on HMM states. Chain initializations set `epsilon` but contain **no explicit JAGS RNG fields**, so an R seed alone does not establish JAGS reproducibility. The package declares JAGS 4 and imports Seurat, RANN, igraph, ape, `parallelDist`, HiddenMarkov, rjags, etc. `R/inferCNV_BayesNet.R:1075-1105,1285-1287`; `DESCRIPTION:16-18`.

## Oracle report/output inventory gate

For every HMM-on case, stage 17 calls `generate_cnv_region_reports` with prefix `17_HMM_pred{resume-token}` and `HMM_report_by` (default `subcluster`). Collect `.cell_groupings`, `.pred_cnv_regions.dat`, `.pred_cnv_genes.dat`, and `.genes_used.dat` together with the state matrix; reports omit the neutral state (`3` i6, `2` i3). Reporting modes `consensus`, `subcluster`, and `cell` change group construction, and a missing subcluster object forces `consensus`. `R/inferCNV_ops.R:270-272,1239-1246,1312-1326`; `R/inferCNV_HMM.R:706-764,790-865`.

For Bayesian-on/non-degenerate cases, capture `BayesNetOutput.{token}/MCMC_inferCNV_obj.rds`, pre/post probability plot inventory if plots enabled, and the adjusted `HMM_CNV_predictions.{token}.Pnorm_{threshold}.pred_cnv_{genes,regions}.dat`; `CNV_State_Probabilities.dat` is written by the step-19 `removeCNV` path, not merely by step 18. These are additional to stage-18/19 checkpoints. The report adjustment reads the original stage-17 gene/region tables. `R/inferCNV_BayesNet.R:613-628,1341-1363,1394-1439`; `R/inferCNV_ops.R:1369-1392,1446-1452`; `R/inferCNV_HMM.R:891-955`. Exact checkpoint filenames are constructed by `.get_relevant_args_list`, not by a generic stage-name formula; `R/inferCNV_ops.R:3407-3496`.
