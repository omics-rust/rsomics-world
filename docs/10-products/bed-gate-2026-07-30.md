# `rsomics-bed` representative product gate — 2026-07-30

Status: representative Linux `x86_64` evidence complete; exact-head
four-native-target CI green; not published.

## Scope

This gate evaluates the five implemented operations: `sort`, `merge`,
`intersect`, `subtract`, and `complement`. It does not add another operation,
revive an operation-sized repository, publish a crate, or invent a new public
foundation.

## Audit correction

The inherited 50,000-record benchmark used non-overlapping A and B records for
intersect and subtract. Both commands produced empty output, so the recorded
72.20x and 68.43x figures measured a sparse no-hit case rather than a
representative hot path.

The sparse case remains a diagnostic, but is no longer a release claim. The
product benchmark now uses:

- ten chromosomes;
- groups of five overlapping intervals for merge;
- one hit for every A record in intersect;
- a duplicate B interval for every fiftieth record;
- two emitted fragments per A record in subtract;
- actual complement gaps.

## Correctness

The existing targeted suite passes 38 library tests, 12 CLI tests, and three
compatibility tests against the real bedtools 2.31.1 binary in both debug and
release profiles.

The control-plane differential runner additionally varied ordering, overlap
density, duplicate intervals, zero-length intervals, chromosomes, and trailing
BED columns. It passed:

- 500 deterministic trials on macOS `arm64`;
- 1,000 deterministic trials on Linux `x86_64`;
- seed `200090385`;
- all five operations per trial.

For sort, bedtools may reorder exact coordinate ties while rsomics deliberately
preserves their input order. The differential therefore requires identical
coordinate ordering and record multiplicity for ties. Other representable
cases require byte-identical output. The already documented origin-zero
fail-loud divergence remains unchanged.

## Performance decision

The host was `dell-Precision-7920-Tower`, Ubuntu 22.04, Linux
6.8.0-90-generic, `x86_64`, with two Intel Xeon Gold 6238R CPUs. Commands were
bound to physical cores 48-51. GNU `time` ran one warmup followed by ten
measurements. Times are means and sample standard deviations; RSS is the
median process high-water mark in KiB.

| Operation | rsomics | bedtools | Speedup | RSS, ours / bedtools | Decision |
|---|---:|---:|---:|---:|---|
| sort | 0.409 ± 0.006 s | 1.071 ± 0.014 s | 2.62x | 198,016 / 360,624 | throughput and memory pass |
| merge | 0.198 ± 0.004 s | 0.225 ± 0.005 s | 1.14x | 2,688 / 4,480 | throughput and memory pass |
| intersect | 1.002 ± 0.008 s | 2.615 ± 0.011 s | 2.61x | 261,140 / 344,960 | throughput and memory pass |
| subtract | 0.960 ± 0.019 s | 2.992 ± 0.017 s | 3.12x | 289,946 / 344,960 | throughput and memory pass |
| complement | 0.239 ± 0.006 s | 0.297 ± 0.007 s | 1.24x | 5,376 / 4,480 | throughput pass; memory tradeoff |

All five operations pass the representative throughput gate. The 1.14x merge
margin is real on this host and distribution, but narrow enough that future
releases must remeasure rather than inherit the claim.

## Foundation and CLI findings

The product directly validates the published interval backend's coordinate
limit before calling its infallible 0.2.0 API. The checked foundation API is
implemented but remains unpublished until `rsomics-annotation` supplies the
second consumer contract. No duplicate replacement index was added.

`rsomics-common` also exposes `--threads` and `--seed` on this command tree.
No current BED operation uses either value, although the default common feature
set initializes a Rayon pool. This is a release-surface blocker shared with
`rsomics-seq`, not evidence that BED should receive speculative parallel or RNG
code.
