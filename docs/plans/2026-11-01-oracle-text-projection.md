## Protocol

One manual ubuntu-24.04 workflow, stdlib controller and single integrated
preparation check. Explicit run ID/artifact ID/expected ZIP digest/root prefix;
repository fixed to omics-rust/rsomics-world. No source runtime/image install,
scientific imports, code execution from the archive, container, build, benchmark,
registry change, notification or scheduler. Parent owns commit/CI/dispatch.

Fetch fresh run/job/artifact metadata, verify exact run/attempt/head binding and
API ZIP digest, then the complete original ZIP hash/CRC and its sole TAR carrier.
Verify the complete TAR manifest, every regular body and symlink target virtually,
reject duplicate/unsafe/special members, and compute the full original TAR hash.
Do not materialize runtime links, binaries or casefold collisions. Current
artifact-manifest.json format is sufficient; do not invent adapters for unrelated
formats or a broad archive framework.

Materialize only original failure/host/storage/integrity/status records and
runtime-check/ldd request/status/stdout/stderr plus R-state namespace/DLL/session
TEXT; cap each selected text at2MiB and all selected text at32MiB. Never deserialize
R objects or activate the runtime. Keep acquisition Authorization on the original
GitHub API request only, not signed redirects; never print/store credentials or
signed URLs. All hosted scratch/caches/outputs under explicit RUNNER_TEMP.

Small delivered proof binds original API identity, ZIP/TAR digests/size, original
manifest hash, every projected path/body hash and captured projection controller
head/files. Archive all partial diagnostics on failure; no empty projection is
success. Upload only projection/proofs, not newly duplicated full originals.
The full original remains the authority; label the new output as a verified
projection, not a historical original sidecar or full local retention receipt.

One stdlib preparation test uses a tiny real ZIP/TAR/manifest with literal body
and link identities, verifies selection/proof and rejects changed/traversal data.
Parent reads all code, runs existing exact-head controller CI, then dispatches
one actual hosted view. No additional helper-level reviewer or science campaign.
